# Онбординг студии

Цель: от анкеты до режима `draft` за один рабочий день. Перед первой реальной клиенткой пройдите гейт пилота (`docs/PRODUCT.md`, раздел 6).

## 1. Данные студии (адмінка)

Основной путь: адмінка `/admin` (вход: `/admin` в Owner Bot или `uv run python -m app.cli admin link`).

1. Попросите у мастера всё, что есть: ответы на анкету (`docs/PRODUCT.md`, раздел 5), прайс, график, текст из Instagram, правила предоплаты, и 20–30 реальных прошлых переписок.
2. «Студії» → «+ Нова студія» → вставьте текст как есть → «Заповнити». AI заполнит форму. Ничего не сохраняется само:
   - жёлтый блок: суммы, которых нет в тексте, проверьте каждую;
   - синий блок: чего AI не нашёл, кнопка копирует вопросы для мастера одним сообщением;
   - красные точки на вкладках: что не проходит проверку.
3. Пройдите вкладки «Основне», «Профіль», «Графік», «Послуги», «Майстри», «Правила», «FAQ і тон» и нажмите «Створити студію».
4. «Тест»: поговорите с ботом как клиентка (видно, какие инструменты он вызвал), затем «Автоперевірка» (10 типовых и каверзных вопросов с оценкой). Всё, что помечено «Проблема», исправьте в данных и сохраните снова.
5. Eval студии для большого пилота: обезличьте переписки и превратите их в кейсы `tests/evals/cases/private/<slug>.yaml` (формат как в `tests/evals/cases/core.yaml`); конфиг выгрузите во вкладке «JSON» в `studios/private/<slug>.json`.
   ```bash
   uv run python -m tests.evals.runner --dir tests/evals/cases/private --runs 3
   ```

Запасной путь без адмінки: `studios/private/<slug>.json` по образцу `studios/demo_studio.json`, затем `make tenant-validate FILE=...`, `make tenant-load FILE=...`, `make tenant-preview TENANT=<slug>`.

Изменения потом: мастер пишет `/change` в Owner Bot, текст приходит основателям. В адмінке «AI-оновлення»: вставить текст, проверить разницу, «Застосувати у форму», «Зберегти». Каждое сохранение — новая версия, откат во вкладке «Історія».

## 2. Owner Bot

1. «Огляд» студии → «Посилання для майстра» (или «Для адміністратора студії»): одноразовая ссылка на 3 дня и готовый текст для мастера. То же: `/link <slug>` у основателей или `uv run python -m app.cli tenant link <slug>`.
2. Мастер открывает ссылку и нажимает «Start». Дальше: `/data` (проверить, что знает бот), `/sandbox` (попробовать как клиентка), `/mode`. Меню команд в Telegram ставит `make webhooks`.
3. Без подтверждения данных мастером (`/data`) запуска нет. Чеклист «Запуск студії» на вкладке «Огляд» показывает, что осталось.

## 3. Канал

### Telegram Business

Требования: Telegram Premium не нужен (`docs/research/telegram-business.md`).

Текст для мастера:

> Відкрийте Telegram → Налаштування → Telegram для бізнесу → Чат-боти. Додайте нашого бота (@назва_бота). У виборі чатів залиште «Нові чати» та «Не контакти», а особисті чати додайте у винятки. Дозвольте боту відповідати на повідомлення. У Telegram для бізнесу вимкніть «Привітання» та «Повідомлення про відсутність», щоб клієнтки не отримували дві відповіді. Поставити бота на паузу в окремому чаті можна прямо в цьому чаті.

Названия пунктов в Telegram могут немного отличаться в разных версиях приложения. После подключения мастер получает в Owner Bot сообщение «✅ Бот підключено…». Если Owner Bot пишет, что аккаунт не привязан к студии, мастер сначала открывает ссылку из шага 2.

Живая проверка: `docs/PRODUCT.md`, раздел 8.

### Instagram

Требования: профессиональный аккаунт; приложение Meta в режиме Live; пока нет Advanced Access, аккаунту студии нужна роль тестера в приложении (`docs/research/instagram.md`). В `.env` должны быть `META_APP_ID`, `META_APP_SECRET`, `META_VERIFY_TOKEN`, `ENCRYPTION_KEY`, `PUBLIC_BASE_URL`; адрес вебхука в кабинете Meta: `https://<домен>/webhooks/instagram`.

1. Сгенерируйте ссылку входа (действует 3 дня, привязана к студии):
   ```bash
   uv run python -m app.cli instagram link <slug>
   ```
2. Текст для мастера:
   > Відкрийте посилання, увійдіть в Instagram-акаунт студії та дозвольте доступ до повідомлень. Після цього вимкніть інші автовідповіді в Instagram (ManyChat, автовідповіді Meta), щоб клієнтки не отримували дві відповіді.
3. Страница «✅ Instagram підключено» значит, что токен сохранён (зашифрованным) и вебхуки подписаны. Токен обновляется сам за 10 дней до истечения; при ошибке приходит алерт.

## 4. Календарь

### Google Календарь

1. В `.env`: `GOOGLE_SERVICE_ACCOUNT_FILE=secrets/google.json` (ключ сервисного аккаунта, вне git).
2. Текст для мастера (вместо `<email>` подставьте `client_email` из ключа):
   > Відкрийте Google Календар на комп'ютері → налаштування календаря, у який записуєте клієнток → «Доступ для окремих людей» → додайте <email> з правом «Вносити зміни в заходи». Щоб закрити день, створіть подію на весь день: бот вважає такий день вихідним.
3. В конфигурации: `"calendar_provider": "google"` и `"google": {"calendar_id": "<id календаря>"}` или `google_calendar_id` у каждого мастера. Id календаря есть в его настройках («Ідентифікатор календаря»).
4. Если мастер удалит событие записи в календаре, бот за час пометит запись отменённой и сообщит мастеру.

### Блокнот, Altegio, Booksy

`"calendar_provider": "lead_capture"`: подключать ничего не нужно. Бот собирает заявку с телефоном, мастер подтверждает время кнопками в Owner Bot.

### Внутренний календарь

`"calendar_provider": "internal"`: часы из конфигурации и записи в нашей базе; закрыть дни можно командой `/close` в Owner Bot.

## 5. Запуск

1. Гейт пилота пройден целиком.
2. Режим `draft` (по умолчанию для новых студий). Через несколько дней без правок — `offhours`, потом `autopilot`, если мастер согласен.
3. Первые 3 дня читайте все диалоги студии ежедневно. Отчёт пилота:
   ```bash
   uv run python -m app.cli tenant stats <slug> --days 14
   ```
