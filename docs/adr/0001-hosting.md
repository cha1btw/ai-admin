# ADR 0001: хостинг бэкенда

- Статус: принято
- Дата: 21.10.2026

## Контекст

Бэкенду нужны: постоянно работающий воркер (очередь, ответы, фоновые задачи), PostgreSQL, HTTPS для вебхуков Telegram и Meta, хранение данных в ЕС (будущие студии в Польше, Чехии, Германии, GDPR), низкая цена и простое обслуживание силами двух основателей. Лендинг — статичная страница.

## Решение

- Один VPS в ЕС (например, Hetzner в Германии или Финляндии), docker-compose из `deploy/docker-compose.prod.yml`: `db` (Postgres 16), `api`, `worker`, `caddy`.
- Caddy получает и продлевает сертификаты сам (HTTPS для вебхуков).
- Ежедневный `pg_dump` (`deploy/backup.sh`) с копией вне сервера и регулярной проверкой восстановления.
- Внешняя проверка `/health` (любой бесплатный uptime-монитор) и алерты в Telegram из кода.
- Лендинг на Vercel как статика.

## Рассмотренные варианты

- **PaaS (Railway, Render, Fly.io).** Проще деплой, но отдельно платим за воркер и Postgres, цена растёт быстрее, меньше контроля над бэкапами. Можно вернуться, если обслуживание VPS станет обузой.
- **Vercel для бэкенда.** Серверные функции не подходят для постоянного воркера, очереди и долгих соединений.
- **Хостинг в Украине.** Риск отключений света и не ЕС.

## Последствия

- Обновления ОС, бэкапы и мониторинг на нас; всё описано в README и `docs/runbook.md`.
- Масштабируемся сначала вертикально (больше VPS); один воркер на старте.
